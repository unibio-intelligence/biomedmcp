# GWAS Catalog association evidence

Use `search` with `entity="gwas"` for individual Catalog associations, `get` with a positive association ID for a record, or `variant_evidence` with a dbSNP rsID and the `gwas` section. All three use GWAS Catalog v2. These are literature-curated top associations, not the complete genome-wide summary-statistics collection. A mapped gene does not establish the causal target gene; an association does not establish a causal variant, clinical classification or experimentally measured variant effect.

Search interprets a canonical rsID as `rs_id`; otherwise the query supplies `mapped_gene` when no explicit gene/trait filter is present. Explicit gene and trait filters are combined, with the standard gene set and direct trait annotations requested. Gene text is a provider gene-filter value, not a newly resolved species-qualified gene identity. Trait text is a provider ontology search, not a service-verified diagnostic identity. The source is human-specific. Returned location strings do not establish their genome build; `coverage.assembly` states that it is unqualified.

Selected minimum contracts validate association/study identities, p-value representations, optional trait/allele metadata, finite effect/interval numbers, typed arrays and coherent page counts before evidence is cached. Unknown additional fields remain under `source_fields` and cannot replace service identities or outcome controls; their semantics are not exhaustively qualified. The retained official schema describes `content` and snake-case page counts, whereas current observed responses use HAL associations and camel-case page counts. Both explicit projections are supported. Missing associations are accepted only when complete, validated page metadata proves an empty requested window. `{}`, incomplete nested rows and application errors never establish absence.

`p_value_status` distinguishes reported numbers, reported components, floating-point underflow, unavailable precision and conflicting representations. Reported mantissa/exponent values are preserved as decimal strings. A returned floating-point zero is not interpreted as an exact zero probability. Conflicting numbers remain separate source assertions. When a p-value threshold cannot be evaluated, the record is retained with a partial outcome; it is not counted as failing the threshold. `coverage` and source pagination retain acquired and filtered counts separately. Risk-frequency/effect text is preserved without inferring units, a control denominator or clinical interpretation.

Search cursors retain provider windows independently of local filtering. A malformed later window preserves earlier associations and provenance with a partial failure. Variant section pagination uses bounded `limit`/`page` parameters and generates canonical, executable `variant_evidence` actions. For example:

```json
{"id":"rs7412","sections":["gwas"],"section_parameters":{"gwas":{"limit":10,"page":0}}}
```

The returned action retrieves the next source page without replaying the prefix. Each request remains subject to authentication, source restrictions and provider budgets. Upstream links are validated as source metadata; their arbitrary URL values never become service execution targets. Page numbers are public window selectors, not secret bearer cursors. Data and counts may change between requests; no release pin or exact replay is asserted.

The [regression suite](../tests/test_gwas_responses.py) includes populated/empty/error/partial projections, missingness, underflow, identity mismatch, source-link validation, cache rejection and actual MCP continuation. [Retained current observations](../tests/fixtures/gwas-contract-2026-10-11.json) qualify selected fields rather than exhaustive source health. See the [official API guide](https://www.ebi.ac.uk/gwas/docs/api/) and [migration guide](https://www.ebi.ac.uk/gwas/docs/news/rest-api-v2-migration-guide/) for provider scope and changing conventions.
