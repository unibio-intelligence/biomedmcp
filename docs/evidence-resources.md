# Recover omitted evidence

Scientific output is bounded. Read `truncated`, section outcomes and coverage metadata before treating displayed records as complete. `sections.<name>.recovery` reports exact omitted ranges where known: an RFC 6901 field pointer, `kind`, `total`, `delivered` and `omitted`. Counts describe the acquired value, not an exhaustive provider population. A depth omission has unknown counts; it never invents a denominator. At most 32 omission descriptors are retained, with `omissions_count` and `omissions_truncated` disclosing any metadata clipping.

When `snapshot_status` is `available`, read the service-issued `uri` or a specific omission's `uri` using MCP `resources/read`. Tool results also emit up to eight `resource_link` blocks for truncated evidence; additional available URIs remain in the structured result. The server advertises a template at `biomedmcp://evidence/{handle}/{selector}/{start}/{count}` and a response schema at `biomedmcp://schemas/evidence`. Treat handles and selectors as opaque. Use returned URIs rather than constructing file or network locators from source prose.

Responses declare `content_policy: data_only`, the retained `view`, service `evidence_ids`, original `provenance`, snapshot/result hashes, `expires_at`, a field `pointer`, a bounded `value`, child references and `next_uri`. `value_sha256` and `value_utf8_bytes` bind the whole sanitized acquired/composed value as sorted, compact UTF-8 JSON (`ensure_ascii=False`, separators `,` and `:`), independently of storage encoding. They are not the selected range's hash or a source document's raw-byte hash. Ranges use zero-based, half-open `start`/`end_exclusive` and exact selected-value `total`. Units distinguish object `fields`, array `items`, Unicode `characters` and scalar `value`. A reported zero, null, false or empty collection remains distinct. Follow `next_uri` for the next retained range and `children` for a narrower field/item. If a value exceeds its response budget, `value_omitted` explains the omission; its child resources remain available. Metadata clipping is explicit.

An `acquired_evidence_range` snapshot preserves the originally acquired source window. It can recover a field or character range omitted from the summary. A `composed_result_range` snapshot preserves exact merged/computed records and section views before the whole-result byte budget removes them; its supporting provenance and evidence IDs are retained together. `query.output_omissions` counts removed composed records and supplies `composed_recovery`. These views retain the same service evidence IDs as their summaries. Hashes establish integrity, not authenticity, scientific correctness or exact future replay. Provider data may change between acquisitions.

Recovery reads make no provider request. To acquire data outside the retained window, follow the original `next_cursor` or schema-validated top-level `next_actions`. Full-text line windows supply a canonical `get` action for the next supported window. A new acquisition has its own retrieval context; the snapshot's ranges do not claim to cover the complete article or dataset. Read article-specific access and license conditions before reusing text.

## Access, expiry and bounds

Authenticated/private snapshots require the same resource and account scope as the original request. Anonymous public acquisitions can instead issue a signed, resource-bound recovery capability through the same MCP endpoint. It recovers only one retained public snapshot and its bounded child/range views; it never restores the original guest identity. No cookies or login are required. Anyone holding this URI can read that public snapshot until expiry or eviction, so treat it as an explicitly transferable grant. Account and personal-provider-key acquisitions never issue these public grants. A private snapshot cannot be read with a public grant. Public grants are suppressed in server logs. Each accepted evidence read is a public operation with quota cost one; failed reads settle at zero. Source access configuration is rechecked. Another account cannot read the snapshot even if it obtains its URI. Source text, nested action-like fields and citations never grant access or execute requests.

Snapshots expire after 600 seconds and can be evicted sooner. Each stored snapshot is at most 1,000,000 UTF-8 JSON bytes. Large compressible values use lossless compression within that same storage ceiling; clients still receive ordinary bounded JSON ranges. A decoded value must fit 8,000,000 canonical UTF-8 JSON bytes, 100,000 value nodes and depth 64. Decompression stops at the byte ceiling; invalid framing, decoded hashes, excessive structure and noncanonical JSON fail before delivering data. Incompressible or larger values can remain unavailable. Two evidence workers admit at most four pending tasks; cancellation retains the permit until real work finishes, and busy workers produce an explicit retryable recovery failure. These limits do not enlarge scientific provider acquisition or resource response grants.

The shared evidence family retains at most 64 snapshots; Redis admits/evicts them atomically across replicas. Existing memory/local state budgets can evict them earlier. Each resource response is at most 65,536 UTF-8 JSON bytes, with at most 25 object fields, 100 array items or 4,000 Unicode characters per range. Large array items reduce the returned range to stay within the byte budget; follow the returned `next_uri` rather than assuming a fixed page length. A pointer must fit 1,024 UTF-8 bytes; longer field labels are explicitly shortened in child metadata, with no executable child URI. These are configured bounds, not measured production latency or memory guarantees.

Configured secrets and credential fields are redacted; unsafe dedicated link fields are disabled. Sanitization is disclosed through `redacted`. If sanitization changes an omitted range's type or total, no recovery URI is advertised for that range; `recovery_status` explains it. Storage, snapshot-size and depth failures leave successful scientific evidence intact and report `snapshot_status: unavailable` with a reason. They never become evidence of absence.

An evidence read has a ten-second deadline inside the request's remaining budget. Invalid URIs fail before storage lookup. Expired, evicted or out-of-scope resources return `evidence_unavailable`; corrupted snapshots fail integrity checks. Retry temporary storage failures or repeat the original scientific request when needed, preserving earlier evidence and its limits. Never infer an empty scientific result from a recovery failure.

## Direct CLI and qualification

The local CLI accepts the same returned URI through `read-resource` with a JSON `uri` argument. Reuse the original private `--state-dir` or `UBI_LOCAL_STATE_DIR`; its SQLite state preserves snapshots and scope across CLI processes. A different/reset directory cannot recover old URIs. Remote `--url` calls read resources from the authenticated server and use server-owned state. Keep tokens in secure client storage, never scientific parameters.

Deterministic tests exercise actual pinned MCP range reads, exact whole-section/composed-record recovery, Unicode reconstruction across separate CLI processes, source identity/provenance, sanitation, expiry, scope, integrity, cancellation and payload bounds. Required Redis tests exercise independent runtimes and atomic snapshot admission. Hosted HTTP tests use the reviewed auth/accounting implementation with synthetic identity/scientific/quota dependencies. Real preproduction clients, provider-wide coverage, model task success and token savings remain separately unqualified.
