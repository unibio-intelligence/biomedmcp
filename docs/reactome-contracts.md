# Reactome pathway evidence

Use `search(entity="pathway",query=...)` for Pathway text matches and `get(entity="pathway",id=...)` for a stable Reactome pathway. Discovery uses the [EMBL-EBI Search Reactome index](https://www.ebi.ac.uk/ebisearch/ws/rest/reactome?format=json), with literal phrase text, forced `type:Pathway` and scientific-species filters, and `start`/`size` pagination. Reactome's ContentService search returns a Solr HTTP 500 even for an unfiltered request. Every page uses the same EBI engine; the service never combines rankings from different engines.

The adapter validates each index entry's numeric database ID against its Reactome stable ID, species, and pathway type. It retains the provider response and hash, total count, observed index release and modification date. Returned records expose index provenance, and a warning explains that this independently updated index may lag ContentService. Index metadata is an observation, not an immutable replay pin. Follow `next_cursor` on the same query and limit; anonymous public continuations work without cookies, while authenticated continuations remain owner-scoped. Explicit zero hits mean no matches in that index; malformed responses and provider failures are errors. Exact retrieval and diagram routes continue to use ContentService and official assets.

Use `get(entity="gene",id=...,species=...,sections=["pathways"])` for species-qualified lower-level memberships. Public gene resolution precedes the documented UniProt mapping endpoint, which accepts gene names. Original Reactome memberships remain provider assertions; source mapping is not independent proof of a causal effect. Human, mouse and rat prefixes are checked against the selected species; other species require explicit matching source species metadata. Disease memberships are included without a hidden disease filter. Failed or malformed acquisition cannot establish that a gene has no pathways.

`get(entity="pathway",id=...,sections=["events"])` retains all contained events, including subpathways and reaction classes. The current `genes` section retains physical participants and their reference entities. A physical participant can be a protein, complex, chemical or set; its identifier is not automatically a gene identifier, and membership is not a pairwise interaction. Inspect `schemaClass` and reference namespaces before making a biological join. Stable pathway identity is checked independently of participant acquisition. Successful peer sections survive a failed acquisition; repeat an unavailable section or report the limitation.

Participant reference entities retain their upstream namespace IDs, such as `uniprot:Q12933` or `chebi:15377`; these are not Reactome pathway IDs. Contained-event responses use database-object identity serialization: a numeric `dbId` reference can point to an event defined inside another object in the same response. The service resolves that reference only from the acquired document, preserving the referenced event's stable ID and source fields. Missing definitions, conflicting definitions and malformed identities fail acquisition rather than becoming empty evidence.

Disease `pathways` sections perform literal Pathway annotation text search. `relation_basis=provider_pathway_text_search` does not verify an ontology mapping or mechanistic disease relationship. The acquired window, total and `exhausted` flag disclose coverage; broader disease-window continuation and ontology mapping remain unqualified. Use ordinary pathway search for its executable continuation.

## Diagrams

Use `query_source(source="reactome",operation="get_pathway_diagram",params={"pathway_id":"R-HSA-109581","output_format":"json"})` for diagram layout JSON. Its `stableId` must match the request. Nodes and edges are geometry, not experimentally measured associations. Empty geometry lists may be omitted by the provider's `NON_EMPTY` serializer. Recover a bounded JSON field through the evidence resource URI supplied with its omission; retain the original evidence IDs.

For `svg` or `png`, the result supplies an external provider asset URL, observed media type, acquired byte count and SHA-256. It checks media/signature and bounded SVG syntax without executing source text or claiming full image/rendering validity. No image bytes or provider instructions become a service action. The current asset URL is mutable; downloading it later is not guaranteed to reproduce the acquired bytes. JSON and image acquisition stop at four million decoded bytes; unavailable large assets are not missing scientific evidence. SVG DTD/entities, excessive depth/elements and malformed signatures fail safely.

Unconsumed species, disease and interaction-class filters were removed from retained adapter schemas. Core pathway tasks remain owned by `search` and `get`; diagram retrieval is the distinct advanced operation. Internal static interaction reads use the documented interactor endpoint and report acquired-page counts, without inventing a total, regulatory classification or species filter. No duplicate public interaction route is introduced.

## Qualification boundary

The fixed source contracts derive from the official [Content Service controllers](https://github.com/reactome/content-service), [search models and converter](https://github.com/reactome/search-core), [graph participant/event models](https://github.com/reactome/graph-core) and [diagram reader](https://github.com/reactome/diagram-reader), observed on 2026-10-11. The test contract fixture records pinned revisions and source hashes. Synthetic actual-MCP tests exercise selected response shapes, identity, continuation, recovery, partial failure, safe errors and source byte bounds. They do not establish exhaustive nested semantics, a current Reactome release identity, experimental truth, causal validity, supported-client/model performance or provider-wide live health. The original ContentService search probes returned HTTP 403 and later HTTP 500; these remain failed observations. The replacement index was observed as release 97 during bounded live checks on 2026-10-16, including from the production VM. Live observations remain separate from deterministic qualification.

Pathway-name discovery rejects unsupported species, assembly and section arguments before contacting sources. Literature relevance is evaluated on acquired records before display excerpts are shortened; shortened nested records retain scoped recovery of their complete text.

Pathway names resolve automatically only when a complete, successful candidate window contains one exact name. Incomplete or ambiguous results require a Reactome stable ID; a match in the first page alone does not establish uniqueness.
