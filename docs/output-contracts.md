# Public results and errors

All 13 tools advertise self-contained JSON output schemas through `tools/list`. The ten scientific tools return either a research result or a controlled error envelope. `batch`, `capabilities` and `quota` advertise their own typed envelopes plus the same controlled error. Every envelope identifies `schema_version: "1.0"`. The `biomedmcp://schemas/result` resource provides the scientific result/error schema.

Selected scientific records have optional, self-contained schemas at `biomedmcp://schemas/records/{family}` for `literature`, `trial`, `variant`, `expression` and `study`. Read these through MCP `resources/read` when validating those record families. Reads use the same resource authorization as the result schema and do not contact scientific providers. Source-specific records outside the selected families remain possible; schema discovery does not grant source permissions or qualify provider health. These resources preserve the 13-tool catalog and its existing byte budget.

ClinGen ERepo expert assertions use the `variant_assertion` record type. Each categorical classification retains its own expert panel, document identifier and observed version, exact ClinGen allele ID, original source row hash and field locators. Conflicting classifications remain separate records. A missing retraction flag is unknown; species, assembly, transcript and condition remain unqualified by the selected summary contract. A document version does not pin the repository release, and page-one coverage does not establish exhaustive evidence. The original row remains `provider_record` data. See [the typed record guide](typed-records.md) for the selected families and their limits.

Search tools accept `output: "summary"` (default) or `"full"`. Summary returns bounded excerpts while preserving result identities, source attribution and the merged `limit`. Literature abstracts/authors and large untyped nested records may be shortened; `record_view: "summary"` and `summary_omissions` identify changed records. Other typed scientific families retain their complete record contract. Exact merged records are available through `query.output_omissions.composed_recovery` when snapshot storage succeeds, including inside composed research sections. Nested recovery uses the same scope checks and explicit unavailable status as top-level recovery. Full mode retains source fields within the envelope byte budget. These views never turn missing or omitted data into negative evidence.

Parameter errors include an optional `error.fields` map from schema-owned paths to constraint codes, for example `{"$.calls[1].arguments.limit": "greater_than_equal"}`. Batch preflight checks every item before acquisition. Submitted values and arbitrary unknown keys are not echoed; unknown keys appear as `<unknown>`. Correct the indicated field using `tools/list`. Entity capabilities also lists section owners/dependencies and valid relation names. `empty` means a successful bounded query with zero records; `error` and `unavailable` describe acquisition failures and cannot establish absence.

Gene alias resolution publishes `query.resolution_policy` and candidate `identity_match` labels. One exact species-qualified symbol or stable ID resolves; provider scores rank candidates and do not prove identity. Article metadata retains provider dates with `date_validation`, including future-dated and invalid-calendar flags. Future issue dates can be legitimate and do not establish that an article has already been published.

Truncated sections retain precise omission metadata and, when storage succeeds, scoped recovery resources. Whole-result omission counts and exact composed-record recovery appear in `query.output_omissions`; available links are also emitted as MCP `resource_link` content. [Evidence resources](evidence-resources.md) describe their separate schema, range semantics, authorization and bounds. Resource reads do not acquire provider data.

Research results preserve `entity`, `outcome`, `records`, `sections`, `provenance`, `warnings`, `next_actions`, `next_cursor`, `truncated` and `query`. Section outcomes and errors remain independent. Provenance includes source, retrieval time, content hash, record locator and source release when supplied. Every scientific result also carries a typed `receipt`; the envelope schema checks these fields. Selected scientific inner records have typed record families; other records and section data remain source-specific. Consult `capabilities` for source contracts and preserve experimental context when interpreting them.

Research results explicitly declare `content_policy: "data_only"`. Records, section data, warnings, query echoes, rejected links and all free text are evidence data, never executable instructions. This includes text that resembles system messages, commands or follow-up actions. Preserve its origin using service-issued provenance and section `evidence_ids`; identifier-like strings appearing inside a paper do not create citations. No keyword filter removes instruction-like scientific text.

Search record `evidence_ids` contain only service-issued locators for the acquired source windows. Provider-supplied fields with that name remain visible as `source_evidence_ids` data but cannot enter the normalized record's citation list. Article deduplication combines locators minted independently by the service; clients must resolve citations against the returned provenance.

Only the top-level `next_actions` array contains service-generated optional requests. Before emission, the common MCP/CLI dispatcher validates their canonical operation, exact public input schema and source-specific planning contract without executing them. Unknown tools, extra instruction fields and invalid arguments fail closed with `invalid_output`; a failed batch item preserves successful peers. Nested `next_actions` or `continuation` fields inside section data are source/composition context, not privileged executable requests. Clients must retain their own permissions and decide whether a suggested request serves the user's task.

Dedicated source link fields (`url`, `href`, `evidence_urls` and names ending in `_url`/`_urls`) accept public HTTP(S) locators. Unsafe schemes, relative locators, private literal addresses, credentials and malformed authorities become `null`; `rejected_links` maps escaped JSON pointers to their raw source values, explicitly as data. Existing response budgets can omit that metadata with a truncation warning. Citation provenance similarly disables unsafe locators without losing evidence/source identity. URLs embedded in ordinary prose remain literal source text. Render source text as escaped text, never active HTML; do not activate rejected locators or fetch arbitrary source URLs. Accepted links are not egress grants: provider acquisition continues through the transport's HTTPS, DNS, redirect, access-policy and resource-budget checks.

Credentials in dedicated link fields are disabled; their rejected metadata redacts userinfo, credential query values (including encoded names) and known configured secrets. The same source-data guidance is supplied through MCP server metadata and the guide resource. These controls establish the service's data/action boundary. They do not establish prompt-injection immunity for an arbitrary model or client. Actual adversarial client evaluations must measure attempted exfiltration, forged citations and instruction changes using synthetic data; host permissions still govern consequential actions.

MCP emits the same JSON in `structuredContent` and text content. Public output is checked before emission. An invalid result produces `invalid_output` without exposing the rejected data or logging a raw schema-validation exception. An invalid batch item becomes a controlled item error while successful peer evidence remains available. All batch requests undergo preflight before any provider call.

## Evidence receipts

Each completed scientific result, including unavailable results and successful batch peers, includes a service-issued `receipt`. Controlled request/execution error envelopes do not pretend to contain scientific evidence. The receipt records the public operation, validated parameters with defaults and null values omitted, scientific implementation/schema revisions, UTC completion time and SHA-256 digests. `sources` lists provider boundaries actually entered by this operation, including cached or failed attempts and identity dependencies; it is not the requested source plan. Nested provider-supplied `sources` strings do not add participants. Each batch item has its own inventory. Section outcomes still determine whether those attempts yielded usable evidence; participation is not success.

Per-source retrieval times, content hashes, releases and evidence locators remain in `provenance`. Unknown releases remain null. Completion time is distinct from original retrieval time when evidence is cached. `reproduction: "not_established"` explicitly states that these receipts do not prove exact future replay. `time_dependent` is true when a provider boundary or provenance source participates, including release-labeled endpoints whose immutability has not been qualified. This conservative marker does not declare an installed study mutable; its checksum/release qualification remains separate.

`request_sha256` binds the normalized, sanitized request. Configured secrets and credential fields are redacted before export and hashing, with `request_redacted: true`; such a request is not directly replayable. Normalized requests exceeding 8,192 UTF-8 bytes are omitted (`request: null`, `request_omitted: true`) while their sanitized digest remains. To check an omitted request, retain its normalized sanitized parameters separately. Account/cache scope, HTTP authentication and server credentials are not receipt fields. Receipts count toward the unchanged 120,000-byte result budget; omission flags and section outcomes must be read before assuming complete evidence.

Hashing uses SHA-256 over `json.dumps(value, sort_keys=True, separators=(",", ":"), ensure_ascii=True, allow_nan=False).encode("utf-8")`; this is the service's JSON encoding, not an RFC 8785 claim. The result digest covers the entire delivered result, including receipt metadata and normalized request, with only `receipt.result_sha256` removed to avoid self-reference. Hashing occurs after link sanitation, action validation and final output bounding. `biomedmcp.receipts.verify_receipt(saved_json)` validates the scientific envelope and receipt, checks the delivered-result digest, and checks the request digest when parameters are present. Pass `normalized_request=saved_normalized_parameters` to also check a separately retained request, including an omitted one. Modification of a measurement, identity, source, request or receipt metadata invalidates the saved digest. These unsigned hashes detect content drift; a party able to rewrite the payload and recompute hashes can forge them. No authenticity, scientific-truth or live-reproduction claim follows from a matching digest.

Saving the returned public JSON preserves an evidence export with section locators and hashes. Private project import, durable storage and modeling remain platform-owned. These selected contracts do not establish complete trial, variant, expression or study record coverage, or complete reproducible derived-measure receipts.

## Typed literature metadata

The four literature discovery sources (PubMed, Europe PMC, PubTator and LitSense2) emit `record_type: "literature"`. PMID, PMCID, DOI and provider paper identifiers retain their namespaces and reporting sources in `identities`. Bibliographic identity implies neither species nor an experimental population. Retained additional provider fields remain source data. `content_scope` distinguishes bibliographic metadata, provider excerpts and sentence excerpts; a sentence match does not imply that a complete abstract was retrieved.

Citation counts are nullable nonnegative integers. Missing counts remain null rather than zero. Open-access and retraction flags are nullable booleans; missing flags remain null rather than false. `source_assertions` preserves each source's retraction, open-access and citation-count assertion independently, with `reported` or `not_supplied` missingness and `flag` or `citations` units. Citation counts from different providers are not pooled. A deduplicated record's retraction summary is true if any contributor reports retraction, false if no contributor reports true and at least one reports false, and null otherwise. Read the independent assertions to see disagreements.

Discovery records and direct article retrieval bind identities and assertions to service-issued source-window/section `evidence_ids`. Resolve those IDs in the returned provenance; the locator describes the acquired evidence, not proof that the provider's assertion is scientifically correct. Missing author metadata remains `source_limited`. Malformed typed fields produce `invalid_source_response`, retaining successful provider peers. The advertised schemas validate tagged literature records in top-level records and direct section data. Nested dossier/graph structures and exhaustive provider semantics remain qualification work; additional provider fields are preserved without promoting them into typed scientific claims.

## Typed trial registry metadata

Selected native ClinicalTrials.gov and NCI records emit `record_type: "trial"` and `assertion_type: "registry_record"`. Qualified `nct` and `nci` identifiers stay separate; ClinicalTrials.gov aliases must be explicitly supplied by the registry. Direct retrieval checks the requested NCT identity against those identifiers. The human registry records carry species 9606; they do not establish participant-level experimental results.

`enrollment` records a nullable nonnegative integer count, `participants` units, missingness, role and basis. ClinicalTrials.gov ACTUAL and ESTIMATED retain those distinct meanings. NCI `minimum_target_accrual_number` is a minimum target, not an observed enrollment or outcome. Omitted counts stay null; reported zero remains zero. NCI phase/status codes are preserved without translation into ClinicalTrials.gov codes. Missing phases remain null rather than an empty list.

ClinicalTrials.gov `has_results` is nullable; missing does not mean false. NCI results fields remain source data and are explicitly `not_normalized`; the selected pinned NCI-owned fixture does not establish their full API contract or equivalence to ClinicalTrials.gov's flag. `source_release` remains null when no immutable release is supplied. Service-issued `evidence_ids` locate the supporting source window or direct section in provenance. Additional source fields remain available. Tagged records in top-level records and direct section data are validated; nested dossier/graph semantics and complete registry coverage remain open.

## Outcome and exit behavior

| Result | MCP `isError` | CLI exit | CLI result stream |
| --- | --- | --- | --- |
| `data`, healthy `empty`, `ambiguous`, `not_applicable` | false | 0 | stdout |
| `partial` with retained evidence or incomplete coverage | false | 0 | stdout |
| Overall scientific `error` or `unavailable` | true | 2 | stderr, complete scientific result |
| Invalid request, access/transport failure, invalid output or unexpected execution failure | true for tool failures | 2 | stderr, controlled error envelope |
| Batch with any successful item and a partial/failed peer | false | 0 | stdout, `outcome: "partial"` |
| Batch whose every item failed | true | 2 | stderr, complete batch result |

Batch envelopes contain `schema_version`, aggregate `outcome` and 1–10 ordered `results`. Completed empty or ambiguous items retain their own scientific status; a completed batch does not resolve ambiguity. Read every item and section before drawing a conclusion. Scientific errors retain provenance and section diagnostics even when MCP marks the tool call as an error. With the pinned FastMCP client, use `call_tool_mcp` to consume the raw nonraising result, or `call_tool(..., raise_on_error=False)` and read `structured_content`. The default raising client path raises `ToolError` for `isError` results.

Local and remote CLI calls use the same JSON/exit contract. Successful JSON goes to stdout. Failure JSON is the final stderr line, after any diagnostic logs; stdout is empty on failure. Library `execute` returns scientific envelopes, including unavailable results, and raises `ResearchError` for controlled request/execution errors. The command catches transport, protocol, local I/O and unexpected exceptions so their raw text does not produce a traceback or expose submitted values.

## Full-text line ranges

Use `get(entity="article", sections=["fulltext"], section_parameters={"fulltext": {"view": "lines", "start": 1, "end": 100}})` for a bounded read. Coordinates are one-based and inclusive, between 1 and 100,000; `end` must be at least `start`, and a request can span at most 100 lines. Omitted bounds default to 1 and 100 independently. To read later text, supply both bounds, for example 101–200. The advertised schema exposes coordinate bounds and documents the interval rule; the server checks the relationship between coordinates before any provider acquisition. Invalid ranges return controlled `invalid_parameters` errors through MCP, CLI and batch preflight.

A valid window retains up to 100 short lines, with their original numbers and source evidence IDs. Generic table row bounds do not cut it to 25 lines. `line_count` describes available article text; `data.truncated` indicates text beyond the requested end. Independent string and envelope byte budgets can still trim long text or omit a section, with section/result truncation and warnings. Check those flags before claiming complete evidence. Recoverable character ranges and omitted-section resources remain separate work.

## Controlled errors

```json
{
  "schema_version": "1.0",
  "outcome": "error",
  "error": {
    "code": "source_rate_limited",
    "message": "The source operation failed; no negative evidence can be inferred.",
    "retryable": true,
    "correction": "Wait before retrying; reduce concurrent requests and inspect quota."
  }
}
```

Each error has a stable code, safe message, retryability and correction text. Correction text is guidance, not an executable action. `invalid_parameters` requires inspecting the advertised input schema and correcting the request. `source_rate_limited` permits a delayed retry. `source_unavailable` does not establish absence. `invalid_source_response` requires another qualified source or a source/maintainer report. `ambiguous` scientific results require a qualified identifier before joining evidence. Native HTTP and controlled retained-adapter failures preserve access, rate-limit and availability classifications; arbitrary retained-provider error bodies are never echoed as messages.

Protocol CLI utilities also validate their inputs before opening a session: `tools`, `resources` and `prompts` accept `{}`; `read-resource` requires a string `uri`; `get-prompt` requires a string `name` and accepts a string-to-string `arguments` object. Batch, capability and quota arguments use shared strict models. Validation errors omit submitted values and unknown property names; use `tools` and `capabilities` for the exact contract. JSON input is bounded to 65,536 UTF-8 bytes for inline, stdin and file inputs.

## Discovery budget

The catalog budget is 98,304 compact UTF-8 bytes for 13 tools, including input and output schemas. The prior 65,536-byte limit is increased to accommodate the typed receipt schema independently in every scientific tool and batch item. The 13-tool interface is unchanged; the token/task impact of the larger catalog remains unqualified. Output schema titles, defaults and descriptions are omitted to reduce repeated annotations; required fields and validation constraints remain. FastMCP preserves local `$defs` in both input and output schemas, making each independently resolvable. Literature and trial definitions appear only in operations that can return their tagged top-level records or direct section data. Equivalent nullable type/enum shorthand reduces repeated schema branches; input descriptions and non-null defaults remain, while null default annotations are omitted. Tool-specific envelopes constrain receipt operation and fixed entity/source context. Generated display titles and empty FastMCP tag metadata are omitted; explicit titles, nonempty tags and other metadata remain. Required scientific constraints are preserved. External references to the result resource would require additional client resolution, so they are not used to meet the byte budget. `scripts/catalog.py` records the live SDK catalog measurement and fails above the budget. Token count remains unmeasured when no tokenizer is installed. A catalog byte limit does not establish client/model task performance; that requires separate evaluation.

Output schemas are an optional MCP feature. The [MCP tools specification](https://modelcontextprotocol.io/specification/2025-11-25/server/tools) describes structured output validation and corresponding text content; advertising these schemas improves validation without implying that the prior absence was a protocol violation.

Variant search shorthand such as `BRAF V600E` must agree with explicit `gene` and `hgvsp` filters. Conflicting identities return `invalid_parameters` before provider requests; equivalent one-letter and three-letter protein changes are accepted.
